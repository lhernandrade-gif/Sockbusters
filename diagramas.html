Estructura del dominio

Modela las entidades del negocio Sockbuster con sus atributos, métodos, asociaciones y multiplicidades. Las clases se agrupan en cuatro paquetes: usuarios y autenticación, catálogo, carrito y pedidos, y reseñas.

Diagrama de Clases — Sockbuster Video & Socks


        


        

          
👤 Usuarios y autenticación
Administrador hereda de Usuario y obtiene TokenJWT (1 → 0..*) con fecha de expiración, base del acceso seguro a funciones administrativas (RNF02).

          
🧦 Catálogo
Cada Producto pertenece a una Categoria y una ColeccionTematica, puede estar inspirado en una Obra (0..1), se ofrece en 1..* Talla y controla su Stock (RF01, RF03).

          
🛒 Carrito y pedidos
Carrito y Pedido se componen (◆) de ítems. El carrito genera un pedido que se procesa mediante Checkout, el cual genera un Pago; el pedido posee un identificador único (RF02).

          
⭐ Reseñas
Un Usuario publica 0..* Resena y cada Producto las recibe. validarPuntuacion() asegura el rango de 1 a 5 estrellas (RF04).

          
🛠 Administración
El Administrador administra productos, obras y stock, y gestiona categorías y colecciones temáticas (RF03).

          
📐 Notación
  • △ generalización (herencia)
  • ◆ composición (ciclo de vida compartido)
  • → asociación dirigida con multiplicidad

🖥 Presentación
La interfaz web (HTML, CSS y JavaScript) agrupa los módulos de catálogo, carrito/checkout, reseñas y administración. En este prototipo corresponde a index.html, catalogo.html y diagramas.html.

          
🔌 Comunicación y servicios
El cliente API consume la API de aplicación por HTTPS. La API orquesta los servicios de autenticación JWT, catálogo, pedidos/checkout, inventario y reseñas; pedidos usa el simulador de pago.

          
🏛 Dominio y persistencia
Los servicios utilizan componentes de dominio que encapsulan las reglas de negocio; estos acceden a los repositorios de datos, únicos responsables de comunicarse con la base de datos.

🔎 Filtrado
El sistema recibe el criterio, consulta los productos de la categoría y bifurca: muestra los resultados o informa que no existen y permite modificar el filtro. Implementado en vivo en el catálogo.

          
💳 Checkout
Incluye dos ciclos: el carrito vacío regresa a agregar productos y el pago rechazado permite reintentar. Al aprobarse, se genera el pedido y se asigna un identificador único (formato SB-AAMMDD-XXXXXX).

Topología e infraestructura

            
Muestra los nodos donde se ejecuta el sistema: el dispositivo del cliente, la CDN en Internet, el servidor web, el servidor de aplicaciones con sus servicios y la capa de persistencia. Todas las conexiones externas usan HTTPS.

Diagrama de Despliegue — nodos y comunicaciones

            

              
              
              
            

          

          

          

        


        

          
⚡ Disponibilidad (RNF01)
El contenido estático se distribuye desde una CDN con caché en el borde, reduciendo la latencia para cumplir una carga inicial menor a 2 segundos. Este prototipo está publicado en Netlify, cuya red global cumple el rol del nodo CDN/Web Server.

          
🔐 Seguridad (RNF02)
El navegador se comunica con la CDN y el servidor web sobre HTTPS/TLS; el servidor web llama a la API también por HTTPS. El servicio de autenticación emite y valida tokens JWT para las operaciones administrativas.

          
🧱 Escalabilidad
Los servicios de catálogo, pedidos, inventario y reseñas se separan dentro del servidor de aplicaciones y comparten una única base de datos, permitiendo escalar horizontalmente la capa de aplicación.
